1. Active Parking Session
When a user selects a parking spot and starts a session:

A session is created storing: user ID, car ID, parking spot ID/location, start time, paid duration (if paid), and status (active / expired / ended)
On the Home Screen, show a persistent session card displaying:

Parking spot name / location
Which car is parked there
A timer counting up (free/unknown duration) or counting down (if the user paid for X hours)
"End Session" button
"Extend Time" button (see below)


Only one active session per car at a time
Session state must survive page refresh — persist in database or localStorage with easy swap to backend later

Extend Parking Time:

A button on the active session card opens a small modal to add time (e.g. +30 min, +1 hour, +2 hours)
Extending updates the session end time and resets the countdown accordingly
Log each extension in the session history


2. Parking Expiry Push Notifications

At 15 minutes and 5 minutes before a paid session expires, trigger a notification
Use the Web Notifications API (Notification.requestPermission()) so alerts appear even when the browser tab is in the background
If the user has not granted permission, show a soft prompt inside the app asking them to enable notifications
Notification content: "⏱ Your parking at [Location] expires in X minutes"
Also add these as in-app notifications in the Notifications page (connected to the existing notifications system)


3. Favorite Parking Spots

On every parking spot marker info window and on the parking spot detail view, add a ⭐ star/bookmark button
Toggling saves or removes that spot from the user's favorites list stored per user in the database
In the Map page, add a "Favourites" filter option that shows only starred spots on the map
In the User Profile or a dedicated Favourites section, show the full list of saved spots with name, zone type, and a "Navigate" button (see Map Enhancements below)


4. User Dashboard
Add a dedicated Dashboard page (or expand the existing home screen) with the following widgets:
Spending Overview:

Monthly bar or line chart (use Recharts or Chart.js — whichever is already in the project) showing total spending per month
Current month total highlighted at the top
Data pulls from paid session history

Most Visited Spots:

Top 3 parking locations ranked by number of visits from the user's parking history
Show spot name, zone color, and visit count
Tapping a spot navigates to it on the map

CO₂ / Environmental Stats (Gamification):

Track distance walked from a parked car to the user's destination (estimated based on parking history)
Show: "You walked X km this month instead of driving further — saved approximately Y grams of CO₂"
Use a fun visual like a leaf icon or progress bar — keep it lighthearted
Calculation can be approximate (distance between parking spot and city center / destination)

Loyalty Points:

Every completed parking session earns points (e.g. 1 point per 10 minutes parked, bonus points for using the app to pay)
Show current points balance prominently on the dashboard
Show a progress bar toward the next reward tier (e.g. Bronze / Silver / Gold)
Redemption: a "Redeem" button lets users exchange points for free parking minutes — show available rewards
Store points per user in the database


5. Notifications & Communication
Extend the existing Notifications page with these new notification types:
Zone Status Alerts:

When a zone the user has previously used or favourited changes its pricing or availability status, generate an automatic notification
Example: "🔵 Blue Zone A pricing has changed — now 1.50 BGN/hour"

Event-Based Warnings:

Super admin can create an event warning linked to a zone or area with a message and time window
Example: "⚠️ Football match near Zone B on Saturday 18:00–22:00 — expect limited availability"
These appear as a special warning card at the top of the Notifications page and optionally as a map overlay banner when the user is viewing that zone

Admin Broadcast Messages:

Super admin can compose and send a city-wide announcement to all users
Appears in every user's Notifications page as a pinned message with an info icon
Super admin sees a "Broadcasts" management panel to view, edit, or delete past broadcasts


6. User Profile & Settings
Extend the existing Profile/Settings page:
Multiple Vehicles:

Users can add more than one car to their account (make, model, plate, color)
Each car is independently selectable when starting a parking session
The My Vehicles page shows all cars as cards with an edit and delete option
Parking history and loyalty points are tracked per car

Language Selector:

Toggle between Bulgarian 🇧🇬 and English 🇬🇧
Use i18n (react-i18next or similar — install if not present) with translation files for both languages
All UI strings must go through the translation layer — no hardcoded English-only text in new components
Language preference is saved per user

Dark Mode:

Toggle between light and dark theme stored in user preferences
Dark mode applies to the full UI including the filter panel, dashboard widgets, session card, and map controls
Use CSS variables or a Tailwind dark class strategy — whichever fits the existing setup
Google Maps dark mode: switch to a dark map style JSON when dark mode is active

Accessibility Settings:

Font size toggle: Normal / Large / Extra Large — applies globally via a root CSS variable
High contrast mode: increases border visibility, button contrast, and text weight for low-vision users
All new components must use semantic HTML and proper aria labels from the start


7. Map — Navigation Integration
On every parking spot marker info window and on the Favourites list:

Add a "Navigate" button (use a navigation/arrow icon)
Tapping it opens an in-app navigation prompt asking the user to choose: Google Maps or Waze
Google Maps: open https://www.google.com/maps/dir/?api=1&destination=LAT,LNG
Waze: open https://waze.com/ul?ll=LAT,LNG&navigate=yes
On mobile these deep-link directly into the native apps
If the user has set a preference before, remember it and skip the prompt next time


8. General Requirements

Do not break any existing functionality
All new UI must be fully responsive — desktop and mobile
Smooth animations on all panels, modals, and transitions — no lag
Use React.memo, useCallback, useMemo throughout all new components
Ask for existing files before touching map component, auth, role logic, data models, or notification system
